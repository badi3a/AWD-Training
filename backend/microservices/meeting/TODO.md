# TODO - Meeting microservice (students)

The service already runs and exposes `GET /api/meetings/hello` with Swagger docs.
Your job: add the **Meeting** logic. **No database**: store meetings in memory (a JS array).

## 1. The Meeting object
| Field | Type | Rules |
|---|---|---|
| id | integer | generated by the server |
| title | string | required, not empty |
| date | string (ISO 8601 date-time) | required, valid date |
| candidateId | integer | required (id from the candidat microservice) |
| jobId | integer | required (id from the job microservice) |

## 2. Endpoints to implement
| Method | Path | Success | Errors |
|---|---|---|---|
| GET | /api/meetings | 200 + list | |
| GET | /api/meetings/:id | 200 + meeting | 404 |
| POST | /api/meetings | 201 + created meeting | 400 |
| PUT | /api/meetings/:id | 200 + updated meeting | 400, 404 |
| DELETE | /api/meetings/:id | 204 | 404 |

Errors must use the same JSON shape as the 404 handler: `{ "status", "error", "message" }`.

## 3. Steps
- [ ] In `src/controllers/meeting.controller.js`: create the in-memory array and write `findAll`, `findById`, `create`, `update`, `remove`.
- [ ] Validate the request body in `create` and `update` (return 400 with a clear message).
- [ ] In `src/routes/meeting.routes.js`: register the 5 routes. Keep `/hello` **before** `/:id`.
- [ ] In `src/config/swagger.js`: add the `Meeting` schema and document the 5 routes (parameters, request body, responses).
- [ ] Check everything in Swagger UI: http://localhost:8083/swagger-ui
- [ ] In `test/`: add tests for each endpoint, then run `npm test`.
