# TODO - Notification microservice (students)

The service already runs and exposes `GET /api/notifications/hello` with Swagger docs.
Your job: add the **Notification** logic. **No database**: store notifications in memory (a Python list).

## 1. The Notification object
| Field | Type | Rules |
|---|---|---|
| id | int | generated by the server |
| recipient | str | required (email or phone number) |
| subject | str | required, max 150 characters |
| message | str | required |
| type | `EMAIL` or `SMS` | default `EMAIL` |
| status | `PENDING` or `SENT` | set by the server, `PENDING` at creation |
| candidateId | int, optional | id from the candidat microservice |
| createdAt | datetime | set by the server |

## 2. Endpoints to implement
| Method | Path | Success | Errors |
|---|---|---|---|
| GET | /api/notifications | 200 + list | |
| GET | /api/notifications/{id} | 200 + notification | 404 |
| POST | /api/notifications | 201 + created notification | 422 (automatic validation) |
| PUT | /api/notifications/{id} | 200 + updated notification | 404, 422 |
| PATCH | /api/notifications/{id}/send | 200, status becomes `SENT` | 404, 409 if already sent |
| DELETE | /api/notifications/{id} | 204 | 404 |

Use `raise HTTPException(status_code=404, detail="Notification 5 not found")` for errors.

## 3. Steps
- [ ] In `app/schemas.py`: write `NotificationCreate` and `Notification` (examples are in comments).
- [ ] In `app/routers/notification.py`: create the in-memory list and the 6 routes.
      Keep `/hello` **before** `/{notification_id}`.
- [ ] Give each route a `summary`, a `response_model` and the right `status_code`: Swagger is built from them.
- [ ] Check everything in Swagger UI: http://localhost:8084/swagger-ui
- [ ] In `tests/`: add tests for each endpoint, then run `pytest`.
