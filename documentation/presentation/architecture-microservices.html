Microservices architecture

Overview of the JobBoard platform: five business microservices, each with its own database, behind an API gateway secured by Keycloak. The services find each other through Eureka, read their configuration from the Config Server and exchange events through RabbitMQ. Everything runs in Docker.

Key points

  • The client only talks to the gateway; the microservices stay in the private network.
  • One database per microservice: no service reads another service's database.
  • Eureka is a directory, not a proxy: calls go straight to the chosen instance.
  • Synchronous call (OpenFeign) when the answer is needed right away; event (RabbitMQ) for work that can wait (e-mail, interview).
