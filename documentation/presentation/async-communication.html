Asynchronous communication (RabbitMQ)

Once an application is saved, candidature publishes the ApplicationSubmitted event. notification sends the “Application received” e-mail and, as a bonus, meeting creates an interview to schedule. The candidate waits for neither of them.

Design rules

  • The producer owns the exchange; each consumer owns its queue.
  • “At least once” delivery: the consumer is idempotent (it remembers the eventIds already processed).
  • If notification is stopped, messages wait in its queue: the application is not blocked.
  • Workshop 5: publish ApplicationWithdrawn (key application.withdrawn) when an application is deleted.

Running RabbitMQ

Docker image rabbitmq:4.3-management, user awd / awd, ports 5672 (AMQP) and 15672 (web UI: http://localhost:15672).
