How Keycloak works

How the gateway protects the API: the application gets a JWT from Keycloak, then sends it with every request. The gateway checks this token with Keycloak's public key before routing, without calling Keycloak on every request.

The eight steps

Getting and using the token

  • 1 The user logs in on the Keycloak page (Authorization Code + PKCE).
  • 2 The application receives an access token (JWT) and a refresh token.
  • 3 Every request carries the header Authorization: Bearer <JWT>.
  • 4 The gateway downloads Keycloak's public keys (JWKS) once.
  • 5 It checks the signature, the expiry, the issuer and the role.
  • 6–8 The request is routed to the microservice; response, or 401 / 403.

Suggested configuration

  • Realm jobboard, public client jobboard-front.
  • Realm roles: CANDIDATE, RECRUITER.
  • Gateway: spring.security.oauth2.resourceserver.jwt.issuer-uri=http://localhost:8180/realms/jobboard
  • Keycloak published on port 8180, because the gateway already uses 8080.
